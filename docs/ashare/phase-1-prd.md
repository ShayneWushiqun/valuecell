# 阶段一需求文档

## 1. 阶段名称

`短周期首页与观察台`

## 2. 阶段目标

阶段一的目标不是做出完整题材系统，也不是先做复杂策略引擎。

阶段一要先把 ValueCell 变成一个：

`用户每天打开后，能在 1 到 3 分钟内知道今天能不能做、该看什么、手里仓位怎么处理的 A 股短周期首页。`

本阶段必须优先解决 4 个问题：

- 今天市场适不适合参与
- 当前情绪周期处在哪个阶段，最近是在修复还是转弱
- 当前最值得关注的主线或方向是什么
- 用户自选股里哪些值得多看一眼
- 用户当前持仓哪些需要处理
- 哪些票还有预期差且今天仍有可参与窗口

## 2.1 当前实现进展

截至当前这一轮实现，阶段一首页已经开始从“欢迎页/持仓摘要页”收敛到“短周期首页与观察台”的目标形态。

已落地的部分：

- 首页第一屏已按工作台顺序展示市场总览、情绪周期、题材趋势、今日操作框架、自选观察、持仓处理和风控建议
- 后端已提供 `/api/v1/homepage/context` 聚合 API
- 首页已真实消费聚合 API，而不是静态文案
- 自选区已改为带状态、涨跌变化和一句话原因的观察池
- 持仓区继续保留原有 CRUD、刷新诊断和摘要刷新能力

当前尚未完全完成的部分：

- 自选观察、持仓动作、风控建议仍主要是轻量规则版
- 部分市场和题材数值口径仍需要继续清洗与校准
- 阶段一完整语义闭环还需要继续补服务层

## 3. 目标用户

### 3.1 核心用户

- 主要交易 A 股的个人投资者
- 典型持有周期在 1 到 2 个月
- 更关注阶段性上涨窗口，而不是三年估值空间
- 能接受波段交易，但很难忍受半年到一年的长时间等待

### 3.2 用户特点

这类用户通常有以下特征：

- 会看消息和题材
- 关注市场热度和赚钱效应
- 会看个股位置和短期趋势
- 不排斥基本面，但不会把财报作为唯一决策依据
- 更在意“现在能不能做”和“该不该先卖”
- 更偏爱中军龙头这类容量够、趋势顺、承接强的票

## 4. 用户核心问题

用户每天打开产品时，最想知道的是：

- 今天整体市场是进攻、轮动还是防守
- 当前情绪周期在哪个阶段，最近几天是向上还是向下
- 今天主要板块和主流题材是加强还是走弱
- 当前主线题材是什么
- 我的自选股里哪几只值得重点盯
- 我手里的票要继续拿还是先减
- 如果今天不适合买，为什么
- 涨停买不进或跌停卖不出时，系统怎么提示我
- 当前高位票还能不能更高，当前低位票是不是还会更低
- 为什么有些票看起来有题材，但一直半死不活，不值得拿

## 5. 阶段一要解决的真实场景

### 场景一：早盘前或开盘后快速判断

用户打开产品，不想先读研究报告，而是先想知道：

- 今天市场状态怎么样
- 最近情绪周期是在回暖、主升还是退潮
- 今天适不适合出手
- 先看哪个方向

### 场景二：盘中看自选

用户看到自选股异动时，希望系统告诉自己：

- 这只是普通波动还是值得重点关注
- 它属于什么方向
- 现在只是观察，还是已经接近可参与窗口
- 当前还有没有预期差，是否已经被一致性打满

### 场景三：盘中或收盘后看持仓

用户手上的票如果冲高回落、放量转弱或所在题材退潮，希望系统告诉自己：

- 这是正常分歧还是风险升级
- 应继续拿、减仓还是卖出
- 结论背后最关键的原因是什么
- 如果短时间大跌，是预期还在的错杀，还是逻辑已经证伪

### 场景四：收盘后复盘次日重点

用户希望系统帮自己压缩信息，得到：

- 今天最重要的市场变化
- 今天情绪周期相对昨天是更强还是更弱
- 明天最值得盯的自选股
- 哪些持仓明天要重点处理

## 6. 阶段一产品原则

### 6.1 首页先给结论，再给细节

首页第一屏必须先给出：

- 市场总览
- 情绪周期
- 主线题材和板块趋势
- 今日重点
- 今日操作框架

然后再进入：

- 个股观察
- 推荐和持仓处理
- 风险控制与分仓建议

不能让用户先面对空白聊天框。

### 6.2 短周期语义优先

页面和建议卡的语言必须围绕短周期表达，例如：

- 今日市场偏进攻
- 当前主线在加强
- 进入重点观察
- 更适合继续持有
- 先减仓等待修复
- 有预期差但不适合追涨
- 高位可继续拿，但不建议新增
- 跌停或大跌后先看预期是否证伪

而不是长期研究型表达，例如：

- 长期价值仍然稳健
- 建议持续跟踪公司基本面变化

### 6.3 建议必须带动作和时间窗

每条建议至少应给出：

- 当前动作
- 核心理由
- 适用周期
- 风险等级

### 6.4 基本面只做辅助

阶段一可以使用财报、公告、业绩信息做排雷和辅助解释，但不能让它取代：

- 市场情绪
- 题材热度
- 资金节奏
- 个股位置

### 6.5 预期差、持续性和可交易性优先

阶段一虽然不做复杂题材引擎，但页面语义和建议卡必须开始体现：

- 这只票或这个方向是否还有预期差
- 当前逻辑是否有持续性
- 当前是否还有可交易性

这里的“可交易性”至少包括：

- 是否已经接近涨停，追买意义不大
- 是否出现跌停或接近跌停的流动性风险
- 当前更适合买入、持有，还是只能观察

### 6.6 高位和低位都不是结论

阶段一产品表达必须避免简单结论：

- 高位票不等于不能继续持有
- 低位票不等于值得抄底

更合理的表达应是：

- 高位但主线仍强，可继续持有
- 高位一致性过强，不建议新增
- 低位但没有承接，继续回避

### 6.7 优先核心票，回避弱票

阶段一虽然还不是完整机会池系统，但首页表达必须开始体现：

- 哪些票是主线里的龙头或中军
- 哪些票只是边缘跟风
- 哪些票热度不够、趋势不顺、容易半死不活

系统应该优先鼓励用户看：

- 趋势顺、量价健康、承接强的核心票

系统应该主动提醒用户回避：

- 热点沾边但不成气候的弱票
- 走势拖沓、总是错过主升的票
- 一旦转弱就更容易阴跌的票

### 6.8 风控和分仓不是附属说明

阶段一首页必须给用户一个基础操作框架，而不是只给观察结论。

至少应包含：

- 今日建议总仓位
- 单票仓位建议
- 是否适合分批建仓
- 是否适合集中在单一题材
- 当前是试错环境还是确认环境

## 7. 功能范围

### 7.1 必做功能

#### 7.1.1 市场温度卡

系统需要在首页给出一个简洁的市场状态判断。

至少应包含：

- 今日市场状态：进攻 / 轮动 / 震荡 / 退潮 / 修复
- 简短说明：为什么是这个状态
- 用户建议：今天更适合追强、低吸、观察还是防守

补充要求：

- 阶段一不追求完全自动化高精度模型
- 允许先使用规则和轻量摘要生成
- 重点是给用户一个明确市场语境

#### 7.1.2 情绪周期卡

系统需要在首页展示一个 A 股短周期常用的情绪周期模型，并记录最近一段时间的
走向。

阶段划分建议采用 6 阶段表达：

- 冰点
- 修复试错
- 主升发酵
- 高潮一致
- 分歧
- 退潮

至少应包含：

- 当前情绪阶段
- 最近 5 到 10 个交易日的阶段变化
- 当前阶段的一句话说明
- 当前阶段更适合的操作方式

补充要求：

- 首页不能只显示“当前情绪强弱”，还要显示最近一段时间的演化轨迹
- 阶段一允许先用轻量规则识别，不要求完美分类

#### 7.1.3 主线题材与重点方向

首页需要展示当前值得关注的 1 到 3 个方向。

每个方向至少应体现：

- 题材名称
- 当前热度或状态
- 简短理由
- 对应代表性股票或用户自选关联
- 当前是否仍有预期差
- 代表股里谁是龙头，谁是中军
- 对应板块最近几日是加强、震荡还是走弱

补充要求：

- 阶段一允许由规则、编辑态配置或轻量归纳生成
- 不要求阶段一就实现完整题材知识图谱

#### 7.1.4 自选观察区

支持用户维护自选股，并在首页右侧或明显区域展示“今日值得看的自选”。

至少应包含：

- 股票代码和名称
- 当前涨跌变化
- 观察状态：普通观察 / 重点观察 / 风险观察
- 一句话原因
- 当前是否可参与：可观察 / 可低吸 / 谨慎追高 / 流动性风险
- 角色标签：龙头 / 中军 / 跟风 / 弱势

补充要求：

- 阶段一继续复用现有 `watchlist` 能力
- 阶段一重点是让自选区更像“观察池”，不是简单股票列表

#### 7.1.5 持仓处理区

支持用户查看当前持仓，并对每只持仓给出短周期动作建议。

每只持仓至少应包含：

- 股票代码和名称
- 成本价与现价
- 当前盈亏或相对表现
- 建议动作：持有 / 减仓 / 卖出 / 观察
- 一到两条核心原因
- 当前适用周期
- 当前预期状态：延续 / 观察 / 证伪风险
- 当前可交易性提示
- 当前角色标签和趋势质量

补充要求：

- 阶段一允许继续复用现有持仓模型和诊断结构
- 但输出语义必须偏短周期，而不是中长期研究语义

#### 7.1.6 每日摘要

系统需要生成一个用户可快速扫读的短周期摘要。

内容至少包含：

- 今日市场一句话结论
- 今日情绪周期变化
- 今日最重要的 3 到 5 条重点
- 今日持仓处理汇总
- 今日自选观察重点
- 今日可参与机会和流动性风险提示

#### 7.1.7 风险控制与分仓建议

系统需要在首页明显区域给出基础风控框架。

至少应包含：

- 今日建议总仓位区间
- 单票建议仓位区间
- 是否建议分批建仓
- 是否建议降低题材集中度
- 当前更适合试错仓、确认仓还是防守仓

补充要求：

- 摘要必须先给“先看什么”
- 不允许只有长篇正文
- 首页应优先展示摘要结论

### 7.2 可选功能

- 用户手动设置自己的操作风格
- 用户设置预计持有天数
- 用户标记某只持仓的核心逻辑

### 7.3 不做功能

- 自动下单
- 高频分时策略
- 复杂题材识别引擎
- 复杂回测体系
- 完整策略 DSL

## 8. 阶段一业务规则

### 8.1 首页展示优先级规则

首页展示层级建议如下：

1. 市场总览和情绪周期
2. 主线题材和板块趋势
3. 今日操作框架和风控分仓
4. 持仓处理
5. 自选观察和机会提示
6. 聊天和通用 Agent 入口

### 8.2 建议卡规则

每张建议卡必须包含：

- 主动作
- 核心理由
- 周期标签
- 风险等级
- 可交易性提示
- 角色或地位提示

可以选填：

- 触发条件
- 失效条件

### 8.3 自选观察规则

自选股至少区分以下状态：

- 普通观察
- 重点观察
- 风险观察

阶段一不要求做复杂评分，但必须有状态差异。

### 8.4 持仓处理规则

每只持仓必须有一个主动作：

- 持有
- 减仓
- 卖出
- 观察

当系统无法得出明确结论时，可以输出“观察”，但必须说明原因。

补充要求：

- 跌停或大跌不等于自动卖出，阶段一允许输出“继续观察”或“可继续持有”
  的结论，但必须明确说明预期是否仍在
- 涨停附近不应默认给出追买建议，应体现“仅适合持有”或“谨慎追高”

## 9. 页面与信息架构

### 9.1 首页

首页是阶段一核心页面，应满足：

- 第一屏就是短周期工作台
- 用户打开后先看到市场和机会语境
- 持仓和自选都能快速进入
- 聊天和 Agent 入口保留，但不应主导第一屏

首页建议区域：

- 市场总览卡
- 情绪周期卡
- 主线题材与板块趋势卡
- 今日操作框架卡
- 今日摘要区
- 预期差机会提示
- 核心票优先观察区
- 持仓处理区
- 自选观察区
- 风控与分仓卡

### 9.2 持仓区

需要展示：

- 当前持仓列表
- 每只股票的动作建议
- 当前盈亏或价格位置
- 风险等级
- 核心理由

### 9.3 自选观察区

需要展示：

- 今日值得看的自选股
- 当前观察状态
- 变化原因
- 是否属于当前主线题材

### 9.4 摘要区

需要展示：

- 今日市场一句话结论
- 今日重点变化
- 今日操作建议汇总

## 10. 核心用户流程

### 10.1 每日打开首页

1. 用户进入首页
2. 系统先展示市场总览和情绪周期
3. 用户查看主线题材与板块趋势
4. 用户查看今日操作框架和风控分仓
5. 用户查看自选观察和持仓处理建议
6. 如需更细分析，再进入聊天或个股页

### 10.2 查看自选机会

1. 用户进入首页或自选区域
2. 系统展示今日重点观察股票
3. 用户快速知道哪些值得多看一眼
4. 用户决定继续观察还是进一步分析

### 10.3 查看持仓处理

1. 用户进入持仓区
2. 系统展示每只持仓的主动作
3. 用户先看需要处理的票
4. 再展开看原因和风险

## 11. 验收标准

- 首页看起来像短周期投资工作台，而不是聊天欢迎页
- 用户进入首页后能先看到市场语境
- 用户能看到情绪周期当前阶段和历史走向
- 用户能快速知道今天先看哪些方向和股票
- 用户能区分哪些票有预期差但还可参与，哪些票只是看起来强
- 用户能看出哪些票是中军龙头，哪些票只是弱跟风
- 自选区不再只是简单列表
- 持仓区能给出短周期动作建议
- 首页能给出基础风险控制和分仓建议
- 摘要区能压缩成用户快速可读的信息

## 12. 验收场景

以下场景全部通过，阶段一才应认为基础合格：

- 用户打开首页后，第一眼能知道今天更适合进攻还是防守
- 用户能看出当前情绪周期处在哪个阶段，以及最近几天是上行还是下行
- 用户能看到至少 1 到 3 个重点方向
- 用户自选股里至少有一部分被区分为重点观察或风险观察
- 用户手里某只票能看到持有、减仓或卖出的主动作
- 用户能看到至少一类“仅适合持有，不宜追买”或“流动性风险”提示
- 用户能看到至少一类“核心票优先”和“弱票降权”的表达
- 用户能看到至少一条明确的分仓或仓位建议
- 页面文案不再是研发说明口吻，而是正式产品语言

## 13. 成功指标

- 首页摘要查看率
- 自选观察点击率
- 持仓处理卡片展开率
- 用户日活中的首页停留时长
- 用户对“今天先看什么”的主观满意度

## 14. 给 AI 开发工具的额外说明

阶段一最容易被做偏成“旧首页上加几个卡片”。

本文件明确要求：

- 首页必须先服务短周期判断
- 聊天区必须降级
- 自选区必须从“列表”升级成“观察池”
- 持仓建议必须改成短周期语义
- 必须开始体现预期差、持续性和可交易性
- 不要在阶段一里提前实现复杂题材引擎
