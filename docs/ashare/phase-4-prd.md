# 阶段四需求文档

## 1. 阶段名称

`股票分析聊天工作区与多上下文研究线程`

## 2. 阶段目标

阶段四的目标，不是再多做一个“聊天框”，而是把当前已经沉淀下来的：

- TradingAgents 分析结果
- 机会池、观察池、题材雷达、提醒、持仓处理
- 决策上下文、时间窗、决策记录与结果回看

组合成一个真正可持续使用的：

`线程式股票研究工作区`

这个工作区需要让用户做到：

- 围绕一只股票或一个题材持续追问
- 在同一线程里切换到别的股票做对比
- 显式看到当前回答依赖了哪些上下文
- 按需追加或移除上下文，而不是被某次报告永久绑死
- 默认先基于已有上下文回答，只有缺信息时才补数据
- 当用户明确要求时，再去调外部数据工具补充分析

## 2.1 当前落地状态

阶段四目前已经完成三轮交付：

- 第一轮：
  - 工作区骨架
  - 研究线程 CRUD
  - 上下文卡片 CRUD
  - TradingAgents run 导入
- 第二轮：
  - `holding / opportunity / watchlist / theme / alert / ticker` 多模块上下文导入
  - 线程消息历史回看
  - 基于当前显式上下文与线程历史的 `context_only` 聊天 MVP
  - `/home/stock-analysis` 可聊天工作区
  - TradingAgents 与机会池 / 观察池 / 题材雷达 / 持仓 / 提醒入口联动
- 第三轮：
  - `StockAnalysisToolPlanner`
  - `context_only / need_tooling / user_forced_tooling`
  - 第一层内部结构化补充 + 第二层日线行情补充
  - 回答依据说明区、工具调用说明区、临时证据补充区
  - `decision_context_window / decision_outcome_review / risk_sizing / decision_effectiveness` 高级研究卡片接入

当前仍未落地：

- 稳定的第三层新闻 / YFinance / 外部解释型补充
- 自动长期记忆
- 自动交易

## 3. 产品核心问题

阶段四需要解决的问题不是“再生成一份报告”，而是：

- TradingAgents 分析完后，用户还有疑问时，如何继续追问
- 同一线程里，如何比较中军、跟风、持仓票和机会池候选
- 用户怎么知道当前回答到底基于哪些信息
- 用户如何手动追加一条提醒、一只持仓、一个题材或一份 run 结果
- 什么情况下应该先直接回答，什么情况下才去查 Tushare、新闻、YFinance
- 外部数据补充后，如何区分“临时证据补充”和“长期上下文”

## 4. 阶段四的核心定位

阶段四不是“TradingAgents 的附属追问框”。

它更准确的定位是：

`一个面向 A 股短周期研究的线程式多上下文分析会话层。`

它要站在现有结构化系统之上，补齐两种能力：

- 多轮研究
- 显式上下文管理

## 5. 核心概念

### 5.1 工作区

工作区是统一入口，不直接等于某一次分析，也不直接等于某一只股票。

它的作用是承载多个研究线程。

### 5.2 研究线程

线程是一个独立研究课题，例如：

- 半导体主线还能不能继续拿
- 算力现在是主升还是补涨尾声
- 某只持仓票要不要减仓
- 某次 TradingAgents 分析结论有没有问题

每个线程都应拥有自己独立的：

- 聊天记录
- 上下文卡片
- 关注股票与题材
- 工具补数历史

### 5.3 上下文卡片

线程中的所有来源信息，都统一收敛成显式上下文卡片，而不是让系统隐式记忆一切。

卡片来源可以包括：

- TradingAgents run
- 持仓
- 机会池候选
- 观察池重点项
- 题材雷达方向
- 提醒项
- 单只 ticker

### 5.4 回答模式

阶段四固定支持三类回答模式：

- 仅基于当前上下文回答
- 缺信息后自动补数再回答
- 用户显式要求补数再回答

### 5.5 临时证据补充

工具补数后得到的新信息，不应自动变成长期上下文。

更合理的方式是：

- 先作为一次临时证据补充参与回答
- 如果用户认可，再手动加入线程上下文

## 6. 必做功能

### 6.1 线程式研究工作区

系统需要提供一个统一的股票分析聊天工作区，至少支持：

- 线程列表
- 新建线程
- 重命名线程
- 删除线程
- 复制线程
- 线程切换

### 6.2 显式上下文管理

系统需要让用户显式看到当前线程挂载的上下文卡片，并支持：

- 查看卡片来源
- 查看卡片摘要
- 删除卡片
- 置顶卡片
- 替换卡片
- 追加卡片

### 6.3 多入口进入线程

阶段四必须支持从以下入口进入分析工作区：

- TradingAgents 分析结果
- 自选观察
- 机会池
- 持仓处理
- 题材雷达
- 提醒中心

### 6.4 多股票对比

用户在同一线程里，应可以把不同来源的股票挂进来进行对比，例如：

- 中军 vs 跟风
- 持仓票 vs 机会池候选
- TradingAgents 分析票 vs 当前主线核心票

### 6.5 按需补数据

默认情况下，系统应优先基于当前上下文回答。

只有在：

- 当前上下文明显不足
- 或用户明确要求补数据

时，才触发外部工具。

当前第三轮实际交付先收口为：

- 默认优先 `context_only`
- 当前问题缺少最新状态时进入 `need_tooling`
- 用户显式点击“补数据后再回答”时进入 `user_forced_tooling`
- 补数结果只作为临时证据补充，不自动升级为长期上下文卡片

### 6.6 回答依据说明

每一轮回答都应尽量给出轻量但明确的“依据说明”，至少能区分：

- 仅当前上下文
- 当前上下文 + 结构化行情
- 当前上下文 + 新闻补充
- 当前上下文 + 多工具补充

### 6.7 线程分叉

用户需要可以基于当前线程复制出一个新线程，用于做分叉研究。

例如：

- 从“半导体主线”线程复制出“半导体中军 vs 跟风”线程

### 6.8 快捷提问模板

线程页应支持少量快捷动作，降低用户组织问题的成本，例如：

- 对比这两只股票谁更强
- 解释当前结论和提醒是否冲突
- 基于当前上下文重述主线逻辑
- 补最新数据再重新判断

## 7. 不做功能

阶段四不应提前扩张为：

- 自动长期记忆系统
- 全市场自动研究线程生成
- 隐式黑盒上下文注入
- 自动交易
- 高频实时盯盘
- 无边界地调用外部搜索和外部数据

## 8. 页面与信息架构

### 8.1 股票分析聊天工作区

建议提供统一页面，例如：

- `/home/stock-analysis`

页面至少包含三栏：

#### 左侧：线程列表

- 当前线程
- 线程标题
- 线程标签
- 最近更新时间
- 当前挂载上下文数

#### 中间：聊天主区

- 多轮问答
- 输入框
- 直接提问
- 补数据后再回答
- 回答依据说明

#### 右侧：上下文卡片区

- 当前挂载上下文卡片
- 卡片详情
- 添加上下文入口

### 8.2 外部入口形态

现有页面不应各自演化出独立聊天系统，而应统一通过入口跳入工作区。

### 8.3 TradingAgents 页面入口

至少应提供：

- 新建分析线程
- 加入现有线程

### 8.4 其他页面入口

至少应提供：

- 从机会池进入线程
- 从持仓进入线程
- 从题材雷达进入线程
- 从提醒进入线程

## 9. 核心用户流程

### 9.1 从 TradingAgents 继续追问

1. 用户查看某次 TradingAgents 分析结果
2. 用户点击“新建分析线程”或“加入现有线程”
3. 系统把该 run 结果转成上下文卡片挂入线程
4. 用户继续提问

### 9.2 从机会池进入对比研究

1. 用户在机会池中发现一只候选票
2. 用户点击“加入分析线程”
3. 在线程中再挂入一只持仓票或一只题材核心票
4. 用户问两者谁更强、为什么

### 9.3 用户要求补数据

1. 用户在当前线程里发问
2. 系统先判断当前上下文是否足够
3. 如果不足或用户明确要求补数据，则调用外部工具
4. 系统输出补数前后的结论变化

### 9.4 线程分叉

1. 用户在某个线程研究到一半
2. 发现需要单独拉出一个子课题
3. 复制当前线程
4. 在新线程里保留必要卡片并继续追问

## 10. 用户价值

阶段四完成后，用户获得的不是一个“更会说话的报告页”，而是：

- 能长期围绕一个研究主题持续追问
- 能显式知道当前判断基于哪些信息
- 能把 TradingAgents、机会池、持仓、题材雷达等信息真正放进一个会话里
- 能在同一线程里做多股票对比
- 能在需要时补数据，而不是每次都被外部噪音打断

## 11. 验收标准

- 用户可以从 TradingAgents、新旧股票页面进入统一工作区
- 用户可以在同一线程里挂载多个上下文卡片
- 用户可以删除或替换上下文卡片
- 用户可以在同一线程里比较多只股票
- 系统默认先基于当前上下文回答
- 系统只在缺信息或用户明确要求时补数据
- 用户能清楚看到回答依据
- 线程之间不会互相污染上下文

## 12. 验收场景

以下场景通过，阶段四基础形态才算成立：

- 某次 TradingAgents 分析后，用户能直接继续追问，而不是只能看静态报告
- 用户可以把一只持仓票和一只机会池候选放进同一线程比较
- 用户可以围绕“半导体”建一个线程，后续再建一个“算力”线程，两者互不污染
- 用户可以在回答后明确知道是否补过外部数据
- 用户可以显式移除某次旧的 TradingAgents run，上下文随之变化

## 13. 成功指标

- 股票分析工作区进入率
- TradingAgents 页面继续追问率
- 线程复用率
- 多上下文线程占比
- 用户主动追加上下文的比例
- 用户主动触发补数据回答的比例

## 14. 给 AI 开发工具的额外说明

阶段四最容易做偏的地方有两个：

- 误做成“TradingAgents 页面里的追问输入框”
- 误做成“隐式记忆一切的聊天黑盒”

本文件明确要求：

- 阶段四必须做成统一工作区，不是只在 TradingAgents 内嵌一个聊天区
- 上下文必须显式可见、可删、可增
- TradingAgents run 只是可选上下文，不是永久绑定关系
- 默认先基于当前上下文回答，再考虑补数据
