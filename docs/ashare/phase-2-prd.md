# 阶段二需求文档

## 1. 阶段名称

`题材监控、机会池与买点系统`

## 2. 阶段目标

阶段二要把系统从“能看今日市场和持仓”升级为“能持续发现未来 1 到 4 周最值得参与的方向和标的”。

本阶段重点解决：

- 哪些政策、消息和题材正在形成阶段性机会
- 用户的自选和候选池里，哪些股票更可能成为近期机会
- 现在是不是合适买点
- 为什么现在只是观察，而不是直接参与
- 哪些机会仍有预期差，且还没因为涨停或一致性过强而失去参与价值

当前真实进度说明：

- 本文档描述的是阶段二目标，不代表当前仓库已经完成阶段二
- 当前已完成的是阶段二 MVP 规则版闭环：
  - `WatchlistObservationService`
  - `ThemeCandidateService`
  - `OpportunityPoolService`
  - `EntryTimingService`
  - `DecisionAlertService`
  - `/home/opportunities` 机会池页面
  - 策略偏好模板 MVP
  - 提醒中心持久化 MVP
  - Agent 裁决上下文 MVP
  - Agent 裁决接口 MVP（默认规则 fallback）
  - 持仓卖点与减仓裁决 MVP
- 当前尚未完成：
  - 真实 LLM / Agent 裁决
  - 完整复杂提醒系统
  - 更细粒度的去重 / 已读 / 历史提醒运营能力
  - 自动交易

补充说明：

- 当前“Agent 裁决上下文 MVP”只负责生成结构化上下文和 prompt preview。
- 当前“Agent 裁决接口 MVP”默认只走规则 fallback，不要求新增 API Key，也不强制接外部 LLM。
- 当前“持仓卖点与减仓裁决 MVP”已覆盖继续持有、持有观察、减仓观察、保护利润、纪律止损五类持仓动作。
- 当前不会自动交易，也不会直接给出绝对化参与指令。

当前系统已覆盖三条主线：

- 买什么：机会池与题材候选排序
- 什么时候买：买点裁决、提醒摘要、裁决上下文与规则 fallback 裁决
- 持仓怎么处理：阶段一持仓诊断 + 持仓卖点与减仓裁决 MVP

## 3. 核心用户问题

阶段二的用户最关心的是：

- 未来一到两周该重点盯哪个题材
- 某只股票是不是这个题材里的核心票
- 现在更适合试仓、等回踩还是继续观察
- 如果题材热，但个股位置太高，系统能不能明确提醒风险
- 某只票是不是还有预期差，而不是已经被交易得太满
- 现在即使看对，是否也因为涨停或流动性问题不值得追
- 哪些票是真正适合重视的中军龙头，哪些票只是半死不活的弱跟风

## 4. 阶段二的核心定位

阶段二不是为了让用户写复杂量化脚本，而是让系统具备：

- 题材和消息监控能力
- 机会池形成能力
- 买点裁决能力
- 预期差和可交易性筛选能力
- 核心票优先排序能力

输出应优先服务：

- 用户自选池
- 用户常看题材
- 用户主动关注的股票

而不是一开始就追求全市场无死角扫描。

## 5. 功能范围

### 5.1 必做功能

#### 5.1.1 题材与方向监控

系统需要持续识别并更新：

- 当前主线题材
- 次主线题材
- 退潮中的题材
- 新启动或升温的方向

补充要求：

- 题材不只靠价格涨跌定义
- 还应结合政策、消息、热度和资金行为
- 阶段二允许从有限数据源先做轻量版本

#### 5.1.2 机会池

系统需要把值得进一步分析的股票放入机会池。

机会池中的股票至少应包含：

- 所属题材
- 当前状态：观察 / 候选 / 高优先级候选
- 简要入池原因
- 当前是否接近买点窗口
- 预期差等级
- 可交易性状态
- 角色标签：龙头 / 中军 / 跟风 / 弱势
- 趋势质量

补充要求：

- 阶段二的机会池要有排序，不是简单列表
- 机会池优先来源于自选池和主线题材代表股
- 机会池应优先体现“能参与”的机会，而不是只收录已经封死涨停的结果
- 机会池排序必须优先青睐中军龙头和强趋势核心票
- 对半死不活、热度不足、承接较弱的票应明确降权

#### 5.1.3 买点判断

系统需要对机会池中的股票输出买点结论。

至少要区分：

- 仍在观察
- 接近可参与窗口
- 已进入高概率买点窗口
- 风险收益比暂不合适
- 逻辑不错但仅适合持有，不适合追买

补充要求：

- 不使用“最佳买点已到”这种绝对表达
- 必须说明为什么是现在
- 必须说明还缺什么确认，或什么情况会失效
- 必须说明当前有没有可交易性

#### 5.1.4 策略偏好与模板

支持用户以较低门槛表达自己的偏好。

阶段二优先支持：

- 题材偏好
- 风格偏好
- 买入风格偏好
- 风险规避偏好

推荐的模板方向：

- 政策催化
- 事件驱动
- 趋势延续
- 回调后二次走强
- 低位启动

补充要求：

- 阶段二以模板和自然语言说明为主
- 不要求自由脚本

#### 5.1.5 主动提醒

当满足关键条件时，系统应主动提醒：

- 某个方向进入重点观察
- 某只股票进入买点候选
- 某只股票从机会池掉队
- 某只股票虽然很强，但当前不建议追买

补充要求：

- 提醒必须可回看
- 同类提醒要有去重
- 同一只股票不应短时间重复轰炸用户

### 5.2 不做功能

- 复杂量化 DSL
- 全市场 tick 级实时监控
- 自动执行交易
- 过度复杂的策略回测

## 6. 阶段二的业务规则

### 6.1 机会池状态规则

阶段二至少区分以下状态：

- 普通观察
- 重点观察
- 候选买点
- 高优先级买点
- 仅适合持有
- 已提醒
- 已失效

### 6.2 买点建议规则

每条买点建议都应说明：

- 当前动作
- 当前所属题材
- 核心理由
- 观察或持有窗口
- 失效条件
- 预期差是否仍在
- 当前是否可参与
- 当前是不是核心票

### 6.3 题材优先级规则

同一时间多个方向并存时，系统需要尽量体现排序：

- 主线优先于次主线
- 加强优先于退潮
- 核心票优先于弱跟风
- 仍有预期差的票优先于已经高度一致的票
- 趋势顺、承接强的中军优先于拖沓弱票

### 6.4 用户偏好规则

用户输入的偏好应优先用于：

- 缩小机会池范围
- 决定提醒优先级
- 决定 Agent 对“适不适合参与”的表达风格

## 7. 页面与信息架构

### 7.1 题材雷达页

需要展示：

- 当前主线和次主线
- 每个方向当前状态
- 方向升温或降温的原因

### 7.2 机会池页

需要展示：

- 今日最值得看的股票
- 所属题材
- 当前候选等级
- 买点建议卡
- 预期差和可交易性标签
- 核心票身份和趋势质量

### 7.3 策略偏好页

需要展示：

- 用户当前关注的风格和题材
- 模板选择
- 自然语言补充说明

### 7.4 提醒中心

需要展示：

- 方向升温提醒
- 买点提醒
- 机会失效提醒

## 8. 核心用户流程

### 8.1 建立偏好

1. 用户选择模板或输入自然语言偏好
2. 系统解析为可监控意图
3. 系统开始围绕用户偏好组织机会池

### 8.2 发现机会

1. 系统监控政策、题材和自选池
2. 筛出进入观察状态的标的
3. 通过 Agent 进一步判断
4. 生成机会池和买点建议

### 8.3 接收提醒

1. 某个方向升温或某只股票进入关键窗口
2. 系统生成提醒
3. 用户进入机会池页查看原因和边界

## 9. 验收标准

- 系统能持续形成题材和方向观察
- 系统能输出有排序的机会池
- 买点建议有动作、有理由、有边界
- 用户偏好能影响候选结果
- 关键机会能形成主动提醒
- 系统能区分“看起来最强”和“仍值得参与”
- 系统能优先把中军龙头排在前面，而不是把弱跟风混在同一层

## 10. 验收场景

以下场景全部通过，阶段二才应认为基础合格：

- 某个政策或事件方向升温后，系统能把相关方向列入重点关注
- 某只自选股被提升为候选买点时，系统能说明原因
- 某只股票条件不够时，系统会输出“继续观察”，而不是强行买入
- 多只股票同时入池时，系统能体现主次排序
- 同一只股票短时间内不会生成大量重复提醒
- 某只票已经接近涨停或一致性过强时，系统能给出“仅适合持有/谨慎追高”
  的结论，而不是盲目给买入提示
- 某个题材里同时有核心票和半死不活的弱票时，系统会优先推荐核心票并明确降低弱票
  的优先级

## 11. 成功指标

- 机会池点击率
- 买点卡片展开率
- 提醒打开率
- 用户添加偏好或模板的使用率
- 用户对“值得看标的”的主观满意度

## 12. 给 AI 开发工具的额外说明

阶段二最容易被做偏成“复杂策略系统”或“量化脚本平台”。

本文件明确要求：

- 阶段二的核心是题材监控和买点判断
- 阶段二的机会池要优先找有预期差且可参与的票
- 阶段二必须把中军龙头优先级显式写出来，不要只做泛题材列表
- 用户表达应低门槛
- 输出应以机会池和建议卡为中心
- 不要过度追求量化 DSL
