# A 股投资助手文档总览

## 1. 背景

ValueCell 当前已经具备以下基础能力：

- 多智能体编排与流式执行能力
- A 股行情、历史价格、基础财务数据接入能力
- 自选股、资产搜索、模拟策略、研究型 Agent 能力

但这些能力还没有被组织成一个真正面向 A 股投资者的产品闭环。当前产品更像一个“能接 A 股数据的 Agent 平台”，而不是一个“围绕用户持仓、自选股、买卖决策持续服务的投资助手”。

本组文档的目标，是将我们已经达成共识的产品方向拆解成可执行的分阶段需求和技术方案。

## 2. 产品总目标

把 ValueCell 演进为一个：

`面向 A 股投资者的、以持仓和自选股为中心的、多智能体决策辅助系统。`

系统最终要持续回答 3 个核心问题：

- 买什么
- 什么时候买
- 什么时候把当前持仓卖掉、减仓或继续持有

## 3. 核心设计原则

### 3.1 以用户资产状态为中心

系统不是从“聊天”开始，而是从以下用户状态开始：

- 当前持仓
- 当前自选池
- 当前策略偏好
- 当前风险承受能力

### 3.2 先解决决策辅助，再考虑自动执行

项目首要目标是帮助用户做更好的研究、跟踪和买卖判断，而不是直接追求全自动实盘。

### 3.3 从信息链下游走向上游

Agent 的价值不只是看 K 线或技术指标，而是将多层信息放到统一时间轴上，形成跨层判断：

- 行情原始数据
- 技术加工指标
- 公告/新闻/事件
- 资金流方向
- 大资金行为节奏

### 3.4 先规则唤醒，再 AI 裁决

不是让大模型 24 小时全市场扫描，而是：

1. 用规则层做低成本筛选和唤醒
2. 用 Agent 对候选机会或风险做综合裁决

### 3.5 所有建议必须可解释

任何买卖建议都必须有结构化输出：

- 建议动作
- 核心依据
- 风险等级
- 置信度
- 触发条件
- 失效条件

## 4. 分阶段路线

## 4.0 当前仓库实现状态

截至当前这轮开发，阶段一最小闭环已经在仓库中落地，当前实现范围如下：

- 已新增持仓实体、持仓诊断实体、每日摘要实体
- 已新增 `portfolio` 后端路由，覆盖持仓 CRUD、诊断刷新、每日摘要查询与刷新
- 已复用现有 A 股适配层能力生成持仓诊断，优先使用 A 股价格、历史行情与新闻线索
- 已复用现有 `watchlist` 体系作为自选体系，不再新增第二套自选模型
- 已将首页主区域改造成“今日摘要 + 我的持仓 + 结构化诊断”，保留原有 Agent 入口

当前仍明确不包含以下内容：

- 阶段二中的策略监控、主动提醒与买卖时机系统
- 阶段三中的跨层信息中台与统一事件模型
- 自动交易、复杂 DSL、多市场支持与高频扫描

### 阶段一：持仓与自选中心

目标：

- 先让系统知道“用户当前持有什么、关注什么”
- 建立日常使用入口
- 做出第一版持仓诊断和风险提醒

目标：

- 持续监控自选池和候选池
- 在满足条件时触发买点/卖点判断

## 4.1 交给 AI 开发工具时的阅读顺序

如果要把本组文档交给另一个 AI 编码工具执行，建议按下面顺序阅读：

1. 先读 [AI 开发交接说明](./ai-dev-handoff.md)
2. 再读本文件，理解总目标和阶段边界
3. 优先读阶段一文档，先完成第一阶段最小闭环
4. 阶段一稳定后，再进入阶段二
5. 阶段三只作为中长期架构目标，不建议与阶段一并行开发

## 5. 阶段边界说明

### 5.1 阶段一不追求

- 复杂自动交易
- 全市场实时扫盘
- 完整跨层事件图谱
- 高复杂度回测引擎

### 5.2 阶段二不追求

- 全量主力行为建模
- 跨层统一裁决中台完全体
- 强依赖私有高成本数据源的能力

### 5.3 阶段三才重点建设

- 统一信息链事件模型
- 跨层时间差观测
- 多 Agent 裁决与复盘闭环

## 6. 推荐执行顺序

建议开发顺序如下：

1. 先完成阶段一，让系统真正具备“用户持仓视角”
2. 再完成阶段二，让系统从“被动查询”变成“主动监控”
3. 最后完成阶段三，建立核心差异化能力

## 6.1 推荐交付方式

为了让 AI 工具更容易稳定产出，建议不要要求它一次性交付全部阶段，而是采用以下方式：

### 第一轮交付

- 仅交付阶段一
- 目标是形成“持仓录入 -> 持仓诊断 -> 每日摘要 -> 首页展示”的完整闭环

### 第二轮交付

- 在阶段一稳定后交付阶段二
- 目标是形成“策略定义 -> 策略监控 -> 买卖提示 -> 主动提醒”的闭环

### 第三轮交付

- 在前两阶段稳定后交付阶段三
- 目标是建立“跨层信息链 -> 时间轴 -> 裁决 -> 复盘”的长期差异化能力

## 7. 当前假设

本组文档默认以下前提：

- 第一目标市场是 A 股投资者
- 初期以桌面端/本地部署体验为主
- 先支持手动录入持仓与策略
- 先支持模拟判断和提醒，不默认走实盘执行
- 允许后续逐步接入更高层的数据源

## 8. 本组文档的使用方式

本组文档不是市场宣传材料，而是开发输入文档。阅读时请默认以下解释：

- “建议”代表结构化决策辅助，不代表投资承诺
- “Agent”代表一个有职责边界的分析模块，不要求一定是独立进程
- “阶段完成”代表可进入下一阶段开发，不代表产品最终完成
- “支持”代表产品与技术链路打通，不代表能力已经达到最优效果
